# Japanese input lexicon expansion — 2026-10-10

The former 479 Hangul-alias entries (179 game-derived) are curated shortcuts, not a general Japanese IME dictionary. Use the same fixture for Android and Swift.

General conversion now also uses the public Mozc lexicon, separately from game content. Source: https://github.com/google/mozc at `18e76511af9371a9a4409b1d13c3e30884b53e9c`. The dictionary is based on IPAdic, with additional Mozc vocabulary; it is not the proprietary Google Japanese Input dictionary. See bundled `ja_lexicon.LICENSE.txt` (Google BSD, NAIST/ICOT notices and Okinawa public domain notice).

Reproduce: checkout that source commit, then `python3 tools/build_japanese_lexicon.py --mozc /path/to/mozc`. Filtering: kana readings <=24 characters, surfaces <=32 characters, general parts of speech cost<=7500, proper nouns cost<=4500 with a 4000 ranking penalty, plus single-kanji vocabulary, lowest-cost 8 distinct surfaces per reading. Entries with ranked cost<=7500 also receive omitted-long-vowel aliases (preserving gemination). Modern standard glyph 充塡 and rare 御璽/朕 are explicit supplements. Manifest records exact size/count/hash; runtime keeps a packed TSV string and row offset array, rather than nearly 492k objects or prefix maps.

The official Agency for Cultural Affairs list is the inventory for 2,136 Jouyou characters:
https://www.bunka.go.jp/seisaku/kokugo_nihongo/kokugo_shisaku/joyokanjihyo_sakuin/
`ja_joyo_coverage.json` records one reading/surface example containing each official character; the Android regression checks that the whole surface is selectable via the real shared lexicon, not only that a glyph exists in the raw file. Glyph coverage is different from correct conversion of every possible sentence or every pronunciation.

Android and iOS call the same sharedCore kana lexicon and beam segmentation code after Hangul-to-kana conversion. The final lexicon contains 491,589 reading/surface rows (340,850 reading keys), 17,319,688 bytes. Existing curated full-word aliases keep priority. General vocabulary follows curated prefix predictions in manual suggestions, commits known full words before literal kana, while sentence guesses follow existing curated segmentation/literal kana in automatic conversion, and retains literal kana alternatives. Both native candidate rows now allow 16 choices via their existing horizontal scroll, so 8 general conversions are not hidden behind 3 predictions and up to 4 literal kana alternatives. Short curated prefixes keep the existing kana automatic-commit behavior. Source costs and bounded segmentation help rank lexical paths; this is not the full Mozc connection-cost/POS engine. General sentence paths require complete known lexical/functional coverage and skip substituted one-kana fragments. Unknown passages fall back to the existing kana/curated behavior instead of manufacturing arbitrary kanji. Ambiguous homophones and unsupported spellings still need user selection; universal contextual conversion is not claimed. The shared daily fixtures test vocabulary outside games and complete inflected sentences.

Both production keyboard extension and native test/toolbar targets explicitly bundle TSV and license. Android packages all shared dictionaries as Java resources. Linux verification of common code is not Swift/Xcode or iPhone memory/device validation. No native iOS archive/TestFlight or AAB is allowed before this APK is approved by the user under the existing release gates.
