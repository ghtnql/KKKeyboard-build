# 게임 종료 전면 광고

정상적으로 마친 연습과 게임에서 점수·진행을 먼저 저장한 뒤, 결과 화면으로 넘어가는 시점에 미리 준비된 전면 광고를 표시한다.

- 기본·단문·변환 연습의 모든 문항 종료, Rain의 시간/생명 소진, Cafe의 모든 주문 종료만 완료 횟수에 포함한다.
- 첫 판에는 표시하지 않는다. 최초 표시도 완료 3판 이상과 최초 광고 상태 생성 후 3분 경과를 모두 만족해야 한다. 실제 전면 광고를 표시한 뒤에는 다시 완료 3판 및 최소 3분을 요구한다.
- 중도 종료·뒤로가기·키보드 확장에는 표시하지 않는다. Rain의 수동 finish도 결과 모델은 completed=true지만 광고 진입 조건에서는 별도로 제외한다.
- 서울 테마 보상 광고가 실제 표시된 경우에도 카운터와 시간 기준을 재설정한다. 보상 광고를 닫았을 때 간격을 다시 계산해 직후 종료 광고가 붙지 않게 한다.
- 빈도 상태는 Android 본체 앱 SharedPreferences와 iOS 본체 앱 UserDefaults에 저장한다. 공통 GameEndAdPolicy를 양쪽에서 사용한다. 키보드 확장에 광고 SDK/저장 브리지를 추가하지 않는다.
- 시작할 때 미리 불러오며 광고 로드 콜백은 캐시만 채운다. 광고 미준비·만료·백그라운드·표시 실패이면 결과로 진행하며 뒤늦게 표시하지 않는다. 캐시는 1시간 미만만 사용한다.
- 표시 콜백은 한 번만 처리하고 지난 광고/지난 세션의 콜백이 새 세션을 끝내거나 빈도를 초기화하지 못하도록 제한한다. 결과 전환에는 뒤로 경로가 있다.

## 광고 설정

Android debug는 Google 공식 테스트 전면 광고 ID를 사용한다. release는 유효한 KK_ADMOB_ANDROID_APP_ID와 KK_ADMOB_ANDROID_INTERSTITIAL_ID가 빌드 환경에 있어야 운영 광고를 불러온다. 미설정이면 광고를 건너뛴다. feedback는 기존 game-free 범위를 유지한다.

iOS Debug 또는 명시적 KKUseTestAds=true 빌드만 공식 테스트 광고를 사용한다. 운영 빌드는 유효한 GADApplicationIdentifier와 KKInterstitialAdUnitID가 필요하다. Xcode INTERSTITIAL_AD_UNIT_ID 설정으로 Info.plist에 전달하며 기본값은 빈 값이다. 앱 타깃만 GoogleMobileAds에 의존하고 extension은 RequestsOpenAccess=false를 유지한다.

현재 실제 운영 광고 단위 ID 설정 및 휴대폰 광고 표시 검증은 하지 않았다. 정식 수익화 활성화와 스토어 개인정보 공개/지역별 동의 설정 확인은 별도의 배포 작업이다. 로컬 개인정보처리방침의 기존 '광고 SDK 없음' 문구는 실제 포함된 SDK에 맞게 수정했으며 공개 웹 정책/스토어 항목을 자동 게시하지 않았다.

## 구매 관련 제안과 범위

사용자가 물어본 가격/위치는 제안이며 이번 종료 광고 구현에 구매 버튼, 결제 SDK, 상품 등록, 테스터 권한을 포함하지 않았다.

시작 가격 제안은 일회성 3,900원, 설정의 테마 항목 아래 '광고 제거'와 구매 복원 경로다. 전체 광고를 건너뛰는 권한이라면 종료 광고 제거와 기존 서울 테마의 광고 없는 접근을 함께 정의해야 한다. 아직 확정된 상품 범위는 아니다.

자체 앱 회원가입 없이 스토어 계정의 구매 내역으로 시작할 수 있다. Android 구매 검증은 Google이 안전한 서버 사용을 권장한다. 테스터 무료 권한은 정식 상품의 Play 프로모션 코드/Apple 인앱 구매 오퍼 코드를 우선 고려한다. 샌드박스 테스트 구매를 정식 권한으로 간주하지 않는다. 플랫폼 간 권한 공유 및 자체 무료 권한 발급·회수에는 사용자 식별/서버 설계를 추가한다.

## 실제 위임

Meta muse-spark-1.3-contributor로 격리 파일 편집을 수행했다. 공통 정책/11개 테스트 작업은 완료 응답이 확인됐다. Android는 최초/좁힌 후속/단일 컨트롤러 수정의 3회 모두 최종 완료 응답에 실패했지만 실제 파일과 부분 수정은 확인·보존했다. 남은 중복/지연/동기 콜백 및 dispose 검토와 5개 추가 테스트만 GPT-6-Sol(medium)에 맡겨 공유 작업공간 결과를 통합했다. gpt-6-sol은 gpt-6.1-sol과 별개의 도구 모델이다.

iOS 첫 작업은 파일 없이 실패했고, 좁힌 두 번째 편집과 공통 정책/SDK 호출/캐시 수정의 세 번째 편집은 완료 응답이 확인됐다. 총괄이 양쪽 플랫폼·공통 UI·설정·개인정보 문서를 연결하고 실제 diff와 테스트를 검증했다. Muse 사용량 수치는 제공되지 않았다.

## 검증 한계

Android 단위/Compose 테스트는 실제 Google 광고 네트워크에서 휴대폰으로 광고를 내려받아 닫는 검사와 다르다. iOS 공통 Kotlin 컴파일은 Swift/Xcode 빌드·SDK delegate·실기기 검증을 대신하지 않는다. APK 전달 후 사용자 테스트를 기다리며 AAB/iOS/TestFlight 빌드·업로드는 실행하지 않는다.

최종 로컬 검증: sharedCore 13개, sharedUI 31개, Android 240개(종료 광고 컨트롤러 13개와 실제 Compose 입력/전환 18개 포함), 총 284개 실패·오류·스킵 0. 기존 콘텐츠 생성 Python 검사 8개도 통과했다. 단문 211개/전체 563개와 기존 네이티브 햅틱·터치 소스가 보존됐음을 확인했다. 광고 닫기 이후 결과 화면 PNG를 직접 확인했다. iOS Simulator arm64 공통 Kotlin 컴파일이 통과했고 iOS 프로젝트/광고 SDK 앱 전용 경계를 정적으로 대조했다.

초기 광범위 allTests 호출은 오프라인 캐시에 없는 iOS x64 리소스 의존성으로 실패했다. 이후 필요한 Android Debug 테스트 및 iOS Simulator arm64 컴파일을 명시해 검증했다. 새 UI 테스트는 IME 액션 직후 전환 LaunchedEffect가 실행되기 전에 값을 읽던 문제를 프레임 대기로 수정한 뒤 전체 Android 검사를 다시 통과했다.
