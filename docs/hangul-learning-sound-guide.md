# 한글학습 발음표와 자모 문항 보완 (2026-10-05)

한글학습에 처음 들어가면 히라가나 발음표가 열린다. 표를 닫거나 취소한 시점에 확인 기록을 저장한다. 이후에는 상단 `?`로 다시 열 수 있다. 안내 확인은 자모 학습 진도를 변경하지 않는다.

자모 카드에는 글자 이름보다 실제 소리를 먼저 표시한다. ㄱ 옆에는 `か き く け こ / が ぎ ぐ げ ご`, `가 기 구 게 고`가 나온다. 기본 24자 모두 동일한 방식으로 안내한다. ㄴ·ㅁ·ㅇ은 받침에서 `ん`과의 근사 대응을 안내하면서 n/m/ng의 차이를 구별한다. 첫소리 ㅇ은 무음이다. 거센소리 및 일본어에 같은 소리가 없는 모음은 별도 설명한다.

발음표는 일본어 소리를 한글로 근사 표기하는 표이고, 자모 카드는 한국어 자모의 소리를 일본어로 안내한다. 따라서 표의 `ち → 치`, `つ → 쓰`를 카드의 `ㄷ → 디·두`와 혼동하지 않는다. 현대 기본 히라가나와 탁음·반탁음 71자를 포함하며, 빈 열도 유지해 아이우에오 열을 맞춘다. 요음·장음·촉음 전체 과정이나 음성 재생은 이번 범위에 포함하지 않는다. 표의 행과 일본어 읽기는 [국제교류기금 『いろどり』의 가나 자료](https://www.irodori.jpf.go.jp/assets/data/Kana_all.pdf)와 대조했다.

자모별 확인 문제의 정답은 해당 첫소리/모음을 포함하고, 세 오답은 해당 첫소리/모음을 포함하지 않는다. ㄱ 문제에서 고한·아사고한·히루고한·반고한만 보여 주는 문항은 생성되지 않는다. 받침을 첫소리로 잘못 세지 않는 기존 규칙은 유지한다. 보기는 실제 출시 rain/cafe의 완전한 단어 묶음에서 가져오며, 인정 정답·별칭 충돌은 양방향으로 제외한다. 한 후보로 네 보기를 만들 수 없으면 다른 후보를 찾는다. 유효한 대안이 있으면 카드 예시와 직전 문항을 피한다. 대안이 모두 무효인 경우에만 예시/제외 문항을 마지막으로 확인하며, 보기 자체를 지어내지 않는다. 별도 단어 퀴즈는 자모 진도를 바꾸지 않는다.

2026-10-05 후속 보완: 학습 카드 예시는 첫 한글 음절의 초성(자음)·중성(모음)으로만 선정한다. 단어 중간에 해당 자모가 있다는 이유로 카드 예시를 재사용하지 않는다. 24자 전체에 정규화한 예시 단어를 한 번씩 배정하고 부족한 자모부터 선정한다. 규우뉴우는 ㄱ에만 표시한다. 카드마다 두 예시를 제공하고, 요청 순서나 예시 개수 변경으로 배정이 달라지지 않는다. 문제 정답의 자모 검사는 기존처럼 단어 전체에 적용하므로 문제 단어의 자모 간 재등장은 가능하다.

학습·퀴즈 단어는 공백을 제외한 한글 표시 5자 이내로 제한한다. `今日も頑張ろう。 → 쿄오모 간바로오` 같은 긴 문장은 이 학습에서 제외하며, 원래 게임 콘텐츠는 삭제하지 않는다. 네 보기의 공백 제외 표시 길이는 모두 같아야 한다. 같은 길이로 세 오답을 만들 수 없으면 다른 정답 후보를 찾고 길이 제한을 완화하지 않는다. 학습 예시가 부족한 ㅑ를 위해 `野菜 → 야사이 (채소)` 한 항목만 공통 rain/cafe 자료에 추가했다. 野菜의 읽기·뜻은 [국제교류기금의 『いろどり』 온라인 교재](https://www.irodori-online.jpf.go.jp/a2-1/learning/01-003-13-01/)와 확인했다. 사용자 콘텐츠 검수 완료를 뜻하지 않는다.

Android/iOS는 공통 Compose 화면·발음 데이터·문항 모델을 사용한다. Android `hangul_learning/hiragana_guide_seen`와 iOS `hangul_learning.hiragana_guide_seen`에 최초 안내 확인을 저장한다. 기존 자모 진도 키와 게임 데이터는 유지한다. iOS 본체 플랫폼은 `IOSKeyboardSettingsPlatform`의 저장 구현을 상속하며, 이 학습 기능은 본체 앱에서 사용한다. 키보드 확장으로 데이터를 쓰는 새 경로는 추가하지 않았다. 표 닫기/취소, 학습 목록, 앱 뒤로/닫기 경로를 유지한다.

검증 결과와 정확한 APK 소스·버전·해시·다운로드·사용자 테스트 상태는 기존 Google Drive `13_개발 진행 현황.md`와 로컬 인계 기록에 남긴다. Linux의 공통 컴파일/Android 검사와 iOS Swift/Xcode/iPhone 검증을 구분하며, 새 iOS 실기기 검증은 아직 완료하지 않았다. APK 사용자 테스트 완료 전 후속 AAB/iOS 배포는 진행하지 않는다.
