# Android/iOS 공통 설정 및 입력 UX 수정

## 변경

- sharedUI 한곳에서 레이아웃 3종 드롭다운, 플릭 거리, 천지인 연속 입력 시간, 테마 선택, 고정 상단 뒤로가기와 키보드 포커스 해제를 제공한다. Android 전용 입력 설정 카드는 제거하고 언어 설정만 유지한다.
- 플릭 키 데이터와 방향/대각선 안정화 판정은 sharedCore에서 재사용한다. Android FlickKeyView와 iOS SharedFlickKeyControl은 터치/표시만 연결한다.
- iOS 본체와 확장은 IOSKeyboardSettingsPlatform으로 같은 설정과 테마 데이터를 사용한다. 본체 앱에서 키보드 설정/테마 버튼을 누르면 Darwin 알림으로 공통 본체 화면에 진입한다. 다른 호스트 앱에서는 같은 Compose 화면을 확장 안에 표시한다. 구형 하단 설정줄과 두 자판 토글은 진입 경로에서 제거한다.
- iOS 확장에는 테마·내리기 버튼과 플릭 입력을 연결한다. App Group 쓰기/광고 SDK는 확장에 추가하지 않는다. 앱/확장의 변경 시각을 비교해 최신 설정을 읽으며 확장의 개인 설정은 확장 로컬 저장소에 쓴다.
- iOS 광고의 Debug 전용 구현을 없애고 실제 보상 콜백 경로를 Release에도 제공한다. TestFlight 워크플로만 공식 테스트 광고를 지정한다. 프로덕션은 실제 광고 ID 설정이 필요하고, 보상 콜백 없이 테마 잠금을 해제하지 않는다. 확장 안의 광고 체험은 본체 앱 이용 안내를 제공한다.

## 확인과 남은 확인

공통 화면의 레이아웃 3종 선택·저장, 스크롤 후 상단 뒤로가기 유지, 입력칸 밖 탭으로 포커스 해제와 입력값 보존을 로컬 Compose 검사와 실제 렌더 캡처로 확인했다. 기존 공통 설정/테마/상용구 화면 검사도 통과했다. 드롭다운의 별도 팝업 창은 Robolectric 캡처 제한으로 이미지에 포함되지 않지만 3종 표시/선택 검사로 확인했다.

iOS 확장이 SharedUI를 사용하도록 연결하므로 Swift 상호운용과 서명된 앱/확장 빌드, 실제 iPhone 확장 실행, cold start/메모리, 설정 전달과 테스트 광고 동작의 추가 검증이 필요하다. Linux의 공통 iOS Kotlin 컴파일 성공을 iPhone 확인으로 보고하지 않는다. APK 확인 전 새 iOS 배포는 기본 승인 절차를 따른다.
