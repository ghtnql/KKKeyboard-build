# 한글 기초 자모 학습

이전 APK 286의 한글학습 버튼은 기존 단어 타자연습을 열었다. 사용자의 ㄱㄴㄷㄹ 학습 요청과 달라 별도 자모 화면으로 수정했다. 홈의 한글 기초/한글학습은 게임보다 위에 있고 기존 단어 타자연습은 단어 연습으로 유지한다. 게임 이름은 한글비와 한글카페이며 일본어는 ハングル雨와 ハングルカフェ, 영어는 Hangul Rain과 Hangul Cafe다.

## 구현

- 공통 Compose 화면에 기본 자음 14개와 모음 10개의 글자·이름·예시 카드 및 네 가지 글자 중 이름에 맞는 글자를 고르는 확인 문제를 제공한다.
- 오답과 카드 열람은 진도에 반영하지 않는다. 정답만 한 번 저장한다. 다시 풀기와 다음 글자, 학습 목록, 닫기 및 앱 상단 뒤로 경로를 제공한다.
- 글자 만들기는 기본 자음과 모음의 140가지 조합을 기존 HangulProbe로 합성한다. 예: ㄴ + ㅓ = 너. 받침·겹자음·복합모음·음성 재생은 이번 기본 24자 과정에 구현하지 않았다.
- 학습 화면은 단어 콘텐츠 JSON이 없어도 열린다. KO/JA/EN UI를 제공하며 학습하는 한국어 자모 이름과 예시는 원문을 유지한다.
- Android 네이티브 AppPlatform은 독립 SharedPreferences의 완료 ID 집합을 사용한다. iOS 본체 IOSAppPlatform이 상속하는 IOSKeyboardSettingsPlatform은 UserDefaults의 별도 키에 중복 없이 저장한다. 게임 XP·키보드 App Group 설정·광고 및 서명 정책은 변경하지 않는다. 자모 진도는 본체 학습용으로 키보드 확장에 표시하지 않는다.

자모 이름은 [국립국어원](https://korean.go.kr/front/mcfaq/mcfaqView.do?mcfaq_seq=5573)의 자모 명칭과 대조했다. 일본어 카페 표기는 [Cambridge 영일사전](https://dictionary.cambridge.org/ja/dictionary/english-japanese/cafe)을 확인했다.

## 검증과 배포 범위

Android 실제 Launcher/네이티브 어댑터를 쓰는 Robolectric 검사에서 오답 미저장·정답 중복 방지·다음 글자·닫기 후 재진입·Activity 재생성 후 진도 복원, 모음 카드와 조합, 콘텐츠 없는 진입을 확인한다. 일본어 자모 화면의 닫기와 기존 게임 입력·광고 종료·음향 흐름도 검사한다. 공통 모델 검사는 알려진 음절, 140개 서로 다른 무받침 음절, 잘못된 자음/모음 인자 순서를 검증한다. 실제 출력 이미지도 확인한다.

iOS 네이티브 진도 복원 XCTest를 추가하고 본체→공통 화면 및 상속된 저장 호출을 정적으로 대조했다. Linux에서는 새 Swift/Xcode 및 iPhone 실행 검사를 하지 않았으므로 iOS 기능 동등성 검증 완료로 표시하지 않는다. 사용자 APK 확인 이후 같은 소스로 iOS 빌드·검사·외부 TestFlight를 진행한다. 현재 스토어 Play 285/TestFlight 19에는 이 기능이 포함되지 않는다.

Muse Spark (`muse-spark-1.3-contributor`, 실제 provider Meta)가 격리 공간에서 UI와 네이티브 저장을 구현했다. 첫 UI 결과의 저장 캐스트·비활성 다음 글자 링크를 검토해 좁힌 후속 작업으로 수정하고 총괄이 실제 코드를 통합했다. 총괄은 컴파일의 한글 문자열 보간 오류를 수정하고 검증·Drive 기록·로컬 APK 전달을 담당했다. GPT 하위 작업자는 사용하지 않았다.

첫 APK 287의 실제 API36 화면에서 학습 완료 체크가 줄바꿈되어 자모 버튼 한 개가 높아지는 문제를 발견했다. Muse에 자모 격자의 버튼 여백과 한 줄 표시만 좁혀 후속 편집을 맡겼다. 학습 완료 버튼과 미완료 버튼의 실제 높이가 같은지 검사도 추가했다. 최종 전달은 이 보정을 포함한 새 소스의 APK 288로 구분하며, APK 287 전달 링크는 사용자에게 최종본으로 제시하지 않는다.
