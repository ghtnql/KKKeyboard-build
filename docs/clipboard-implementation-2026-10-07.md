# 클립보드 구현·검증 기록 (2026-10-07)

## 범위와 기준

사용자 지정 `clipboard-platform-plan-2026-10-07.md`를 구현한다. 시작 소스는 `80d11b3`이며, APK308의 `975edef` 이후 천지인 누름 순서 수정까지 포함한다. 기존 공유폴더 APK308/스토어307 기록과 구분한다.

Android는 시스템이 접근을 허용하는 동안 최신 클립을 수집하고, 일반 기록30개와 고정30개를 별도로 유지한다. 키보드가 숨겨진 동안 복사된 모든 중간 기록을 복원할 수 있다고 보장하지 않는다. iOS는 자동 수집 없이 명시적으로 가져온 텍스트만 수동 저장한다. 두 플랫폼 모두 정확한 원문 기준 중복 제거, 최근 사용 순서, 개별 삭제, 확인 후 전체 삭제, 고정, 재시작 후 유지, 긴 미리보기 축약을 목표로 한다. 저장은 항목당 UTF-16 10,000단위로 제한하고 초과 원문을 임의로 잘라 저장하지 않는다.

## iOS 권한 및 검증 경계

`RequestsOpenAccess=false`를 유지한다. 키보드 자체 저장 영역에 저장하며 App Group 쓰기에 의존하지 않는다. Apple의 최신 [Open Access 문서](https://developer.apple.com/documentation/uikit/configuring-open-access-for-a-custom-keyboard)는 이 상태에서 자체 컨테이너와 공유 컨테이너 읽기만 허용한다고 설명한다.

[UIPasteControl 문서](https://developer.apple.com/documentation/uikit/uipastecontrol)에 따라 iOS16 이상은 명시적 시스템 붙여넣기 컨트롤을 사용한다. 이 API의 일반 설명을 키보드 확장에서의 권한/실기기 성공 증거로 삼지 않는다. 가져오기 실패/사용 불가 때 호스트 입력창의 시스템 붙여넣기 경로를 안내한다. 자동 감시, 권한 우회, 전체 접근 권한 변경은 포함하지 않는다. 추가 대안으로 사용자가 호스트 입력창에 붙여넣고 선택한 글을 `UITextDocumentProxy.selectedText`로 명시적으로 가져와 저장/고정할 수 있는 버튼을 제공한다. 이 경로도 실제 iPhone 검증은 남아 있다.

## 수용 기준

- Android: 민감 표시 클립은 미리보기/자동·수동 저장에서 제외, 명시적 붙여넣기만 가능. 비밀번호 필드에서 기록 수집/패널 진입 제외. URI를 강제로 텍스트로 읽지 않는다.
- Android: 삭제한 같은 클립이 패널 새로고침이나 키보드 재표시만으로 다시 저장되지 않아야 한다. 입력 종료 시 리스너/패널 정리.
- 공통: 조합 중 붙여넣기 시 조합을 먼저 확정하고 원문을 정확히 한 번 입력한다. 기록을 키보드 입력 버퍼와 분리한다.
- UI: 기존 높이 안의 스크롤 패널, 고정/일반 구분, 닫기, 좁은 폭에서도 툴바 접근 가능. iOS 키보드 내리기 제공.
- 검증: 저장소 및 실제 서비스 경로 회귀, Android 렌더·상호작용 확인. Linux의 정적 검사만으로 Swift/Xcode/iPhone 성공을 선언하지 않는다.

## 상태

구현 중. 테스트·빌드·기능 동등성 완료가 아니다. 새 APK 이전에 공유폴더 진행 문서에 정확한 소스를 기록·재읽기한다. 새 APK 사용자 테스트 전 AAB/iOS/TestFlight 실행은 하지 않는다.
